# Ejercicio 3.2 · Subclase de `java.io.File`

## Código original

```java
package laboratorio;

import java.io.File;

public class MiArchivo extends File {
    public MiArchivo() {
        System.out.println("Mi Archivo instanciado");
    }
}
```

## ¿Compila?

**No.** El compilador rechaza el constructor con un error como:

```
MiArchivo.java:5: error: constructor File in class File cannot be applied to given types;
    public MiArchivo() {
                       ^
  required: String
  found:    no arguments
  reason: actual and formal argument lists differ in length
```

## Por qué falla

El constructor de `MiArchivo` no invoca explícitamente a ningún constructor de
la superclase, así que el compilador inserta una llamada implícita a `super()`,
es decir al **constructor sin argumentos** de `java.io.File`.

El problema es que `File` **no tiene** constructor sin argumentos. Sus
constructores públicos son:

| Constructor | Descripción |
| --- | --- |
| `File(String pathname)` | a partir de una ruta |
| `File(String parent, String child)` | ruta del padre + nombre del hijo |
| `File(File parent, String child)` | objeto padre + nombre del hijo |
| `File(URI uri)` | a partir de un URI `file:` |

Como `File` declara constructores propios, el compilador **no** le genera el
constructor por defecto. Por lo tanto el `super()` implícito no encuentra
destino y la compilación falla. Es el mismo mecanismo que provocó el error del
punto [3.1.c](3.1.md).

El diseño de `File` es deliberado: un objeto `File` representa una ruta del
sistema de archivos, y una ruta vacía no tendría sentido. La clase obliga a
proveerla en el momento de la construcción.

> Nota: `File` representa la **ruta**, no el archivo en disco. Instanciarlo no
> crea ningún archivo — de hecho `exists()` puede devolver `false`.

## Solución implementada

Está en [`3.2/laboratorio/MiArchivo.java`](3.2/laboratorio/MiArchivo.java). Se
invoca explícitamente a un constructor válido de `File` como primera sentencia.

**Solución 1 — propagar la ruta (la recomendada):**

```java
public MiArchivo(String pathname) {
    super(pathname);
    System.out.println("Mi Archivo instanciado: " + getAbsolutePath());
}
```

**Solución 2 — conservar el constructor sin argumentos, dándole una ruta por defecto:**

```java
public MiArchivo() {
    super("archivo_por_defecto.txt");
    System.out.println("Mi Archivo instanciado (ruta por defecto): " + getAbsolutePath());
}
```

La solución 1 respeta el contrato de `File`; la 2 solo sirve si la aplicación
tiene un archivo predeterminado con sentido. Ambas están implementadas para
poder comparar.

Se agregó además `private static final long serialVersionUID = 1L;` porque
`File` implementa `Serializable` y toda subclase serializable debería declararlo
(si no, `javac -Xlint:serial` emite una advertencia — no es un error).

## Compilar y ejecutar

```bash
cd "Practica 1/ejercicio 3/3.2" && javac laboratorio/MiArchivo.java TestMiArchivo.java && java TestMiArchivo
```

`javac` necesita que el archivo esté en un directorio que coincida con el nombre
del paquete (`laboratorio/MiArchivo.java`), y `java` se ejecuta desde el
directorio **padre** de `laboratorio/`.

## Regla general que deja este ejercicio

Al heredar de cualquier clase, hay que verificar qué constructores ofrece la
superclase. Si **ninguno** es sin argumentos, todo constructor de la subclase
está obligado a empezar con un `super(...)` explícito.
