# Ejercicio 1

## Respuestas

**a)** Si la pila se recorre mediante sucesivas llamadas a `pop()`, puede
recorrerse una sola vez: cada lectura elimina el elemento del tope. Para volver
a recorrerla habría que cargarla nuevamente.

**b)** `Stack.StackIterator` implementa `Iterator<String>` y recorre el arreglo
interno desde el último elemento hasta el primero, es decir, en orden LIFO. El
iterador no elimina elementos de la pila.

**c)** Cada llamada a `iterator()` construye un iterador nuevo, con su propio
índice. Por eso la pila puede recorrerse todas las veces que se desee. Además,
al implementar `Iterable<String>`, puede usarse un `for-each`.

**d)** Sí, mientras `StackIterator` sea accesible. Como no es `static`, primero
se necesita una pila y luego se usa la sintaxis:

```java
Stack pila = new Stack();
Stack.StackIterator it = pila.new StackIterator();
```

La instancia del iterador queda asociada a `pila`.

**e)** Se declara la clase interna como `private`. De ese modo solo `Stack`
puede hacer `new StackIterator()`, mientras que los clientes obtienen un
`Iterator<String>` mediante el método público `iterator()`:

```java
private class StackIterator implements Iterator<String> { /* ... */ }
```

En esta entrega se la mantuvo `public` para que
`TestStackIteratorExterno.java` pueda demostrar concretamente la respuesta d).

java -cp out practica3.Stack
java -cp out practica3.TestStackIteratorExterno
