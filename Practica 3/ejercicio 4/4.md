# Ejercicio 4

1. **Falsa.** Una clase anónima no tiene nombre, por lo que no se puede escribir
   otro `new NombreDeLaClaseAnonima()` en un punto diferente. La expresión que
   la declara sí puede ejecutarse muchas veces (por ejemplo, dentro de un
   método), produciendo una instancia nueva en cada ejecución.

2. **Verdadera.** Son habituales para crear objetos función, listeners,
   callbacks, comparadores o tareas breves en el lugar donde se necesitan. Si
   la interfaz es funcional, desde Java 8 muchas de estas situaciones también
   pueden expresarse con una lambda.

3. **Falsa.** `instanceof` puede comprobar la superclase o cualquiera de las
   interfaces con nombre que tenga el objeto; no hace falta que la interfaz sea
   *marker*. Lo que no se puede comprobar es el tipo exacto de la clase anónima,
   porque carece de un nombre que pueda escribirse en el programa.

   ```java
   Runnable tarea = new Runnable() {
       public void run() { }
   };
   System.out.println(tarea instanceof Runnable); // true
   ```

4. **Verdadera, si se refiere a la declaración directa.** La sintaxis de una
   clase anónima permite indicar un solo tipo: o se extiende una clase o se
   implementa una interfaz. No existe una cabecera anónima con `extends` e
   `implements`, ni una lista de varias interfaces. Se puede obtener esos tipos
   indirectamente usando como base una clase que ya implemente interfaces o una
   interfaz que extienda varias interfaces.
